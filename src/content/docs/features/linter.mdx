TangleGuard provides also a structural linter, to keep your project's architecture in place - also when working in large teams.

This CLI tool only verifies your source code regarding the defined dependency rules which you define via the TangleGuard Designer, see [here](/designer/layer).


## Configuration File 

The configuration made within the desktop app (the *designer*), are stored in a JSON file named `tangleguard.json` in the root of your software project.

<FileTree>

- src/
- Cargo.toml
- **tangleguard.json**

</FileTree>

If you use the Desktop App for the first time, TangleGuard will create that file for you. The file is supposed to be included in Git. Below are some advantages listed to have such file.

<Aside type="tip" title="Architecture Definition File">
- Architecture commitments directly within the codebase
- Structured way to track changes of your architecture
- Let's you review architectural changes
</Aside>

Below you see an example configuration.

```json
{
  "layers": [
    {
      "name": "Interaction",
      "description": "",
      "packages": ["rest-api", "graphql-api"]
    }
  ],
  "packages": [
    {
      "name": "rest-api",
      "dependencies": ["utils"],
      "focus": "technical"
    }
  ],
  "rules": [
    {
      "from": "Interaction",
      "to": "Services"
    }
  ],
  "domains": [
    {
      "name": "User Management",
      "dsl": ["OAuth", "Token", "Role"],
      "domain_type": "Generic"
    }
  ]
}
```

You can edit the file manually but it's highly recommended to use the UI instead.

<Aside type="note">
  If you make changes to the configuration file directly, there is a change that
  the data is not consistent anymore. E.g. if you rename a layer, make sure you
  rename the layer also within the rules. To omit this problem, it's recommended
  to adjust the configuration only via the UI.
</Aside>
