TangleGuard provides also a structural linter, to keep your project's architecture in place. 
The architecture decisions can be defined in a configuration file and TangleGuard verifies the source code regarding the defined dependency rules.

## Configuration File 

The architecture configuration is stored in a YAML file named `tangleguard.yml` in the root of your project. This file is supposed to be included in Git, to share it across your team and have a architecture versioning.

<FileTree>

- src/
- Cargo.toml
- **tangleguard.yml**

</FileTree>

Below you see an example configuration.

```json
{
  "group": [
    {
      "name": "Interaction",
      "description": "",
      "packages": ["rest-api", "graphql-api"]
    }
  ],
  "rules": [
    {
      "from": "Interaction",
      "to": "Services"
    }
  ],
}
```

You can edit the file manually but it's highly recommended to use the UI instead.

## Check for violations
You can validate the dependencies of your codebase in multiple ways:

- Using the CLI: `tangleguard check`
- Using the Desktop App: Click on the "Check" button in the UI
