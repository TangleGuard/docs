TangleGuard is also a **structural linter**, which keeps your project's architecture in place.
It verifies the source code regarding predefined rules.
Later custom rules will be enabled again too.

## Check for violations

You can validate the dependencies of your codebase in multiple ways:

- Via GitHub Action, see [GitHub Actions](/apps/action)
- Using the Desktop App: Click on the "Check" button in the UI (todo)
- Using the CLI: `tangleguard validate`

## Custom Dependency Rules

<Aside type="caution">Custom rules are under construction.</Aside>
The architecture decisions can be defined in a configuration file.

The architecture configuration is stored in a YAML file named `tangleguard.yml` in the root of your project. This file is supposed to be included in Git, to share it across your team and have a architecture versioning.

<FileTree>

- src/
- Cargo.toml
- **tangleguard.yml**

</FileTree>

Below you see an example configuration.

```json
{
  "group": [
    {
      "name": "Interaction",
      "description": "",
      "packages": ["rest-api", "graphql-api"]
    }
  ],
  "rules": [
    {
      "from": "Interaction",
      "to": "Services"
    }
  ]
}
```

You can edit the file manually but it's highly recommended to use the UI instead.
